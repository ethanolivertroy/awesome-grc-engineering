# Contribution Guidelines

Please note that this project is released with a [Contributor Code of Conduct](code-of-conduct.md). By participating in this project you agree to abide by its terms.

---

## Adding to this list

Please ensure your pull request adheres to the following guidelines:

- Search previous suggestions before making a new one, as yours may be a duplicate.
- Make an individual pull request for each suggestion.
- Use the following format: `[Title](link) - Description.`
- Link additions should be added to the bottom of the relevant category.
- New categories or improvements to the existing categorization are welcome.
- Check your spelling and grammar.
- Make sure your text editor is set to remove trailing whitespace.
- The pull request and commit should have a useful title.
- The body of your commit message should contain a link to the repository.

Thank you for your suggestions!

## Quality Standards

For GRC tools and resources, please ensure:

- **Actively maintained:** Last commit within 12 months (unless mature/stable)
- **Documentation:** Clear README with setup instructions
- **Relevance:** Direct application to GRC engineering (not just generic compliance)
- **Production-ready:** Battle-tested in real GRC workflows (note maturity level if early-stage)
- **Open-source preferred:** Commercial tools welcome if genuinely valuable, but note licensing

## What Qualifies as GRC Engineering?

This list focuses on *engineering* approaches to GRC, aligned with the [GRC Engineering Manifesto](https://grc.engineering):

**Included:**
- Automation and tooling for compliance workflows
- Policy as Code implementations
- Infrastructure as Code (IaC) for compliance
- Continuous compliance and assurance tools
- Evidence automation and collection
- GRC APIs and integrations
- Security automation frameworks with GRC application

**Not Included:**
- General compliance consultancies (no engineering focus)
- GRC theory without implementation guidance
- Enterprise vendors without engineering/automation angle
- Certification prep only (must teach principles)
- Marketing content or vendor-sponsored materials

## Dual Audience

This list serves two audiences. When suggesting resources, consider noting which audience benefits most:

- **GRC professionals:** Learning technical implementation, automation, coding
- **Security engineers:** Learning business risk context, compliance frameworks, GRC processes

Resources that bridge both perspectives are especially valuable.

If maintainers request changes, edit your existing PR rather than opening a new one. [Here's a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md) on updating PRs.
