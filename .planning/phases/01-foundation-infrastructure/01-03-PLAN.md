<task type="auto">
  <name>Task 1: Generate TOC with doctoc</name>
  <files>README.md</files>
  <action>
Run doctoc to populate the table of contents between the doctoc markers in README.md.

```bash
npx doctoc README.md --title '## Contents'
```

This will:
1. Find the `<!-- START doctoc -->` and `<!-- END doctoc -->` markers
2. Generate a table of contents from all headings
3. Insert it between the markers
4. Use "## Contents" as the title (matching awesome convention)

After running, verify the TOC section is populated (not just the markers).
  </action>
  <verify>Run: grep -A5 "START doctoc" README.md | grep -q "- \[" && echo "TOC populated"</verify>
  <done>README.md has populated table of contents between doctoc markers</done>
</task>

<task type="auto">
  <name>Task 2: Run awesome-lint and fix any issues</name>
  <files>README.md</files>
  <action>
Run awesome-lint to validate the repository.

```bash
npx awesome-lint
```

Common issues to watch for (from STACK.md Section 2.1):
- `awesome-badge`: Badge missing or not immediately after title
- `awesome-list-item`: Description formatting (must end with period)
- `unordered-list-marker-style`: Must use `-` for all list items
- `trailing-slash`: URLs shouldn't end with `/`
- `awesome-git-repo-age`: Repo must be 30+ days old (will fail until then - this is expected)
- `awesome-github`: Missing topics (will fail until topics added via GitHub UI)

**Expected failures for new repos:**
- `awesome-git-repo-age` - Cannot be fixed, repo needs to mature
- `awesome-github` - Requires manual GitHub topic configuration

For other errors:
1. Note the exact error message
2. Fix the issue in the relevant file
3. Re-run `npx awesome-lint` until only expected failures remain

Document any fixes made in the summary.
  </action>
  <verify>Run: npx awesome-lint 2>&1 | tee /tmp/lint-output.txt; grep -E "(awesome-git-repo-age|awesome-github)" /tmp/lint-output.txt && echo "Only expected failures" || (grep -q "0 errors" /tmp/lint-output.txt && echo "All passing")</verify>
  <done>awesome-lint passes with only expected failures (repo age, GitHub topics) or zero errors</done>
</task>

<task type="auto">
  <name>Task 3: Configure GitHub topics via CLI</name>
  <files>None (GitHub API)</files>
  <action>
Configure the required GitHub topics using the GitHub CLI.

```bash
gh repo edit --add-topic awesome-list --add-topic awesome --add-topic grc --add-topic compliance --add-topic governance --add-topic security-automation
```

Required topics (per STACK.md Section 1.1):
- `awesome-list` (required for awesome ecosystem)
- `awesome` (required for awesome ecosystem)

Recommended additional topics for discoverability:
- `grc` (domain-specific)
- `compliance` (domain-specific)
- `governance` (domain-specific)
- `security-automation` (domain-specific)

If gh CLI is not authenticated, this will need to be done manually via GitHub web UI:
1. Go to repository Settings
2. Under "Topics", add: awesome-list, awesome, grc, compliance, governance, security-automation
3. Save

Note: This task may require GitHub authentication. If `gh auth status` shows not authenticated, the executor should authenticate first with `gh auth login`.
  </action>
  <verify>Run: gh repo view --json repositoryTopics -q '.repositoryTopics[].name' | grep -q "awesome-list" && echo "Topics configured"</verify>
  <done>Repository has awesome-list and awesome topics (plus GRC-specific topics)</done>
</task>
